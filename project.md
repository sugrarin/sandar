# SANDAR — тренажёр устного счёта

**Продакшн:** [sandar.kz](https://sandar.kz)  
**Репозиторий:** [github.com/sugrarin/sandar](https://github.com/sugrarin/sandar)

## Состояние проекта

SANDAR — работающий mobile-first тренажёр устного счёта на казахском и русском языках. Основной игровой сценарий доступен без регистрации. Аккаунт добавляет облачную статистику, достижения, совместный просмотр прогресса и AI-сводку.

Актуальная базовая версия использует Next.js 16.3.4, React 19, TypeScript, Zustand и Supabase. Production build, линтер и unit-тесты входят в обязательную проверку перед изменениями.

## Реализовано

### Тренировки

- Шесть режимов: сложение, вычитание, умножение, деление без остатка, таблица умножения и смесь четырёх базовых операций.
- Четыре уровня сложности: Easy, Medium, Hard и Brain. Hard и Brain в 20% случаев используют предыдущий уровень для плавного разогрева.
- Раунд из 12 вопросов с четырьмя уникальными вариантами ответа.
- Мгновенная подсветка правильного и неправильного ответа.
- Повтор вопросов, в которых была ошибка. Разбор ошибок не записывается как новая тренировка и не увеличивает статистику.
- Конфетти при идеальном результате.

### Аккаунт и данные

- Вход по одноразовому коду на email через Supabase Auth; SMTP настроен через Resend.
- Игра без аккаунта. Завершённые раунды временно хранятся в `localStorage` и синхронизируются после входа; очередь ограничена 50 раундами.
- Для авторизованного пользователя сохраняются агрегат раунда, длительность и первый ответ на каждый вопрос.
- Общая статистика, статистика по режимам и сложности, 26-недельная тепловая карта и недельный график точности.
- XP, уровень, серии идеальных раундов и серия дней. Серия дней и XP показаны в шапке и профиле.
- 11 достижений с прогрессом и уведомлением о разблокировке.

### Совместный доступ

- Ученик получает восьмизначный код и ссылку доступа.
- Родитель или учитель активирует код после входа и получает доступ только для чтения.
- Доступны профиль ученика, общая статистика, XP, серии, активность и статистика по режимам.
- Ученик может отозвать доступ, родитель или учитель — отвязать ученика.
- Статистика учеников предварительно загружается и кешируется на время сессии интерфейса.

Подробная история раундов и отдельные ответы ученика пока не показаны в интерфейсе совместного доступа.

### AI-сводка

- Пользователь подключает собственный Gemini API key; ключ хранится в его профиле Supabase.
- Браузер напрямую обращается к Google Gemini API с моделью `gemini-3.1-flash-lite`.
- В сводку передаются агрегаты: количество тренировок и примеров, общая точность, ошибки и показатели четырёх базовых операций.
- Ответ кешируется и автоматически пересоздаётся после изменения статистики; также доступно ручное обновление.
- Обработаны неверный ключ, rate limit, отсутствие данных, сетевые ошибки и пустой ответ.

### Интерфейс и платформа

- Адаптивная вёрстка от 320 px, светлая и тёмная темы.
- Казахский и русский интерфейс с сохранением выбранного языка.
- Web App Manifest и standalone-режим установки на домашний экран.
- Error Boundary, skeleton-состояния и уведомление об ошибке сохранения.

Полноценного offline cold start нет: service worker и кеш приложения не реализованы. Без сети можно продолжить уже открытую тренировку, но открыть приложение с нуля офлайн нельзя.

## Архитектура

```text
app/
  api/
    activity/          # активность текущего пользователя
    sessions/          # сохранение и получение раундов
    stats/             # агрегированная статистика
    share/             # коды, связи и статистика учеников
  share/page.tsx       # активация ссылки общего доступа
  layout.tsx
  manifest.ts
  page.tsx

components/            # экраны и переиспользуемые UI-компоненты
contexts/              # стек внутренней навигации
lib/
  ai/                  # Gemini-клиент, промпт и payload
  supabase/            # browser/server клиенты
  achievements.ts
  session.ts           # сохранение и offline-очередь
  sessionPayload.ts    # формирование запроса сохранения
  translations.tsx
  xp.ts
stores/                # Zustand: игра, статистика, аккаунт, AI
tests/                 # unit-тесты Vitest
types/                 # доменные типы и настройки сложности
proxy.ts               # locale cookie и обновление Supabase-сессии
```

## Локальный запуск

```bash
npm ci
npm run dev
```

Переменные окружения:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

Проверки:

```bash
npm test
npm run lint
npm run build
```

## База данных

Для нового окружения нужно последовательно применить в Supabase SQL Editor:

1. `schema.sql` — основные таблицы, триггеры и RLS.
2. `migration_share.sql` — таблицы и функции совместного доступа.
3. `migration_gemini_api_key.sql` — колонка Gemini API key, если её ещё нет в `profiles`.
4. `migration_share_security.sql` — проверка авторизованного пользователя внутри `SECURITY DEFINER` функций. Эта миграция обязательна и для уже работающего окружения.

`migration_share_update.sql` сохранён как историческая миграция и для нового окружения отдельно не требуется.

## Ограничения текущей реализации

- Сохранение сессии и её ответов выполняется двумя запросами к Supabase без общей транзакции. Нужны RPC-функция или идемпотентный `client_session_id`.
- Unit-тестами покрыты генерация задач, варианты ответа и формирование payload сессии. API, Supabase и пользовательские сценарии пока не покрыты интеграционными и E2E-тестами.
- Web App Manifest есть, service worker отсутствует.
- Gemini API key хранится в профиле и используется на клиенте; отдельного серверного AI-прокси и шифрования ключа нет.
